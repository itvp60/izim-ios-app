# IZIM ID — приложение для записи NFC-меток

Мобильная оболочка (Expo / React Native) вокруг **id.izim.kz**: клиент заполняет
профиль в существующем веб-конструкторе и сам записывает ссылку `https://id.izim.kz/t/КОД`
на NFC-браслет — на iPhone и на Android. Реализация следует плану
`IZIM NFC — мобильное приложение для записи меток` (v2.0, 27.08.2026): гибрид
"нативное ядро (NFC) + WebView только для форм профиля".

## Что реализовано (Этап 1 — MVP)

- **Мои браслеты** — локальный список записей на устройстве (`expo-secure-store`),
  статусы `draft → written → locked`.
- **Профиль (WebView)** — открывает `id.izim.kz/setup` (создание) или секретную
  ссылку `editUrl` (редактирование существующего профиля). Слушает
  `postMessage` `{type:'profile-saved', code, profileUrl, editUrl}` от страницы.
- **Запись метки** — инструкция → `NfcManager.requestTechnology(Ndef)` → запись
  NDEF URI-записи → **обязательное перечитывание и сверка ссылки**.
- **Блокировка** — отдельный экран с переключателем-подтверждением, отдельно
  от записи, с явным предупреждением о необратимости.
- **Прочитать метку** — диагностика любой метки: ссылка, тип, ёмкость,
  свободное место, заблокирована ли.
- **Помощь** — где антенна на iOS/Android, как включить NFC, частые проблемы.
- Все сценарии ошибок из раздела 8 плана (заблокированная метка, чужие данные
  с подтверждением перезаписи, преждевременное отведение телефона, метка
  недостаточной ёмкости, NFC выключен, устройство без NFC, нет сети).
- Офлайн: `src/storage/claimQueue.ts` — пул заранее полученных кодов и очередь
  подтверждений "записано"/"заблокировано", которая досылается на сервер при
  появлении сети (`src/sync/flushPendingSync.ts`, слушатель `NetInfo` в `App.tsx`).

## Структура

```
App.tsx                     точка входа: NavigationContainer, NfcManager.start(), NetInfo
src/
  navigation/                стек экранов (RootNavigator.tsx, types.ts)
  screens/                   6 экранов из раздела 4 плана
  nfc/                       nfcManager.ts (write/read/lock + обязательная верификация),
                             errors.ts (типизированные ошибки NFC)
  storage/                   braceletsStore.ts (SecureStore), claimQueue.ts (AsyncStorage)
  api/                       client.ts, tags.ts, profiles.ts — под два недостающих
                             эндпоинта бэкенда (раздел 6 плана)
  sync/                      flushPendingSync.ts — досылка офлайн-очереди
  types/, theme/, components/
```

## Что нужно на бэкенде (раздел 6 плана) — ещё не реализовано на id.izim.kz

| Метод | Эндпоинт | Для чего |
|---|---|---|
| `POST` | `/api/tags/claim` | выдать пачку кодов+ссылок для офлайн-записи (`src/api/tags.ts`) |
| `GET` | `/api/profiles/mine` | восстановить список профилей устройства по edit-токенам (`src/api/profiles.ts`) |
| — | страница `/setup` (веб) | добавить `window.ReactNativeWebView.postMessage(...)` на экране «Готово» |

Контракты этих вызовов в коде — наше предположение (см. комментарии в
`src/api/tags.ts` и `src/api/profiles.ts`), их нужно сверить с бэкенд-командой
до релиза. Приложение не блокируется на них: до появления `claim`/`mine` можно
пользоваться только веткой «создать профиль → сразу записать метку».

## Запуск

NFC не работает в Expo Go — нужен собственный dev-build.

```bash
npm install
npx expo install --check   # выравнивает версии под установленный SDK
eas login
eas build --profile development --platform ios      # или android
```

После установки dev-client на телефон:

```bash
npx expo start --dev-client
```

`npm run typecheck` — проверка типов без сборки.

## Известные риски (раздел 11 плана), актуальные для кода

- **Блокировка на iOS** сделана через `NfcManager.ndefHandler.makeReadOnly()` —
  общий метод библиотеки для обеих платформ. Его поведение на iOS нужно
  проверить на реальном железе в Этапе 0; если Core NFC не даёт заблокировать
  метку тем же вызовом, что и Android, потребуется нативный патч поверх
  `react-native-nfc-manager` (см. `src/nfc/nfcManager.ts:lockTag`).
- Разбор ошибок NFC (`src/nfc/errors.ts`) основан на текстах сообщений
  библиотеки, которые могут отличаться между Android/iOS и версиями ОС —
  сверить и расширить `MESSAGE_PATTERNS` по итогам теста на матрице устройств
  из раздела 10.
- Иконка, сплеш, тексты витрин, Privacy Labels / Data Safety — это Этап 2 и
  сюда ещё не добавлены.

## Bundle / package ID

`kz.izim.id` — домен компании (раздел 7.5 плана), не привязан к личному
Apple/Google аккаунту Улданы, что делает будущий перенос на юрлицо стандартной
процедурой Apple App Transfer.
